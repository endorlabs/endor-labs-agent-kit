# VS Code Host — Design Spec

Status: implemented (compiler + publisher + guardrails + tests landed)
Owner surface: `endor-labs-agent-kit` (this repo) → synced slice in `endorlabs/ai-plugins`

This document specifies a new **VS Code** host for the Endor Labs Agent Kit at
full parity with the Cursor/Gemini/Antigravity packages. It is the authoritative
target for the upstream compiler/publisher work and for the downstream mirror
integration. It does **not** hand-author the generated slice — that is emitted by
the compiler like every other host.

---

## 1. Rationale and boundary

### Why VS Code

VS Code now ships a first-class agentic development experience: agent mode with
custom instructions, prompt files, **custom agents** (`.agent.md`, renamed from
the legacy `.chatmode.md`), **Agent Skills** (`SKILL.md`, the same open standard
Claude/Cursor use), and MCP via `.vscode/mcp.json`. The Agent Kit already targets
Claude Code, Codex, Codex-directory, Cursor IDE, Cursor SDK, Gemini CLI, and
Antigravity CLI, but has **no VS Code target**. A VS Code host closes that gap for
the largest editor install base with no new source recipes — the existing 11
workflow recipes plus 1 setup skill render into VS Code's native shapes.

### Where the work lives (repo-role clarification)

The plan that seeded this spec described the working repository as the generated
mirror `endorlabs/ai-plugins`. In fact this repository is the **upstream source
repo** `endorlabs/endor-labs-agent-kit`:

- Source of truth: `source/agents/<id>/{recipe.yaml,instructions.md,actions.yaml}`.
- Compilers: `src/endor_agent_kit/compilers/<host>.py` render a recipe into
  host-native artifact text.
- Publishers: `src/endor_agent_kit/publication/<host>_plugin.py` assemble the
  on-disk plugin package.
- Generated slices land under `plugins/<host>/endor-labs-agent-kit/` and are then
  synced byte-for-byte into `ai-plugins` by
  `scripts/sync_ai_plugins_distribution.py`.

So the VS Code host is **implemented here** (new compiler + publisher + guardrail
checks + tests + catalog/provenance) and its generated `plugins/vscode/` slice is
emitted here. The `ai-plugins` mirror then receives that slice through the normal
sync PR and its boundary validators are extended to recognise it.

The mirror rule that "everything under `plugins/<host>/` is synced byte-for-byte
and hand-editing is forbidden" still holds: even in this repo, `plugins/vscode/`
is a compiler output, never hand-authored. Every generated file carries the
`endor_agent_kit_managed=true` marker and the "Generated by Endor Labs Agent Kit"
comment, and `docs/distribution-sync.md`'s `diff -qr` loop guards it in the
mirror. That is why the in-repo deliverable is this spec, not a hand-written
slice.

## 2. Format spec

### 2.1 Mapping table

The Agent Kit renders the same 11 workflow recipes + 1 setup skill into each
host's native shape. VS Code's native shapes (confirmed from
code.visualstudio.com docs):

| Agent Kit concept | VS Code artifact | Notes |
| --- | --- | --- |
| Workflow subagent (`recipe.yaml`) | `.github/agents/<id>.agent.md` | Frontmatter: `name`, `description`, `tools` (array), `model` (name or priority array), `user-invocable`, `disable-model-invocation`, `target: vscode`. Body = notice + VS Code Host Contract + recipe body. Renamed from legacy `.chatmode.md`. |
| Workflow skill | `.github/skills/<id>/SKILL.md` | **Open Agent Skills standard — identical shape to Claude/Cursor/Gemini `SKILL.md`.** Frontmatter `name` (must equal dir name, lowercase/hyphen, ≤64) + `description` (≤1024, includes *when to use*). No namespace prefix in `name`. |
| Setup skill | `.github/skills/endor-agent-kit-setup/SKILL.md` | Reuse existing `source/plugin-support/setup/setup.md` body, VS Code wording. |
| Global guardrails / knowledge pack | `.github/copilot-instructions.md` | Applied to every request in the workspace automatically (no frontmatter needed — that is what distinguishes it from `.github/instructions/*.instructions.md`, which use `applyTo`). Carries safety rules + "do not assume Endor MCP is configured." |
| Endor MCP server | `.vscode/mcp.json` | **KEY DIFFERENCE:** VS Code uses top-level `"servers"`, NOT `"mcpServers"` (which Claude/Cursor/Codex/source `.mcp.json` use). See §2.5. |
| Large-result helper | `runtime/summarize_endor_artifact.py` | Referenced by skills via relative Markdown links. |

**Full parity = render BOTH `.github/agents/*.agent.md` and
`.github/skills/<id>/SKILL.md`** — exactly like the Gemini/Antigravity packages,
which ship both `agents/` and `skills/`. Agents populate the agent dropdown and
are model-invocable subagents; skills are relevance- and slash-invocable.

### 2.2 Proposed slice layout

Emitted upstream at `plugins/vscode/endor-labs-agent-kit/`, synced verbatim into
the mirror:

```
plugins/vscode/endor-labs-agent-kit/
├── README.md
├── .github/
│   ├── copilot-instructions.md
│   ├── agents/<id>.agent.md            # 11 workflow agents
│   └── skills/<id>/SKILL.md            # 11 workflows + endor-agent-kit-setup
├── .vscode/mcp.json
├── runtime/summarize_endor_artifact.py
└── assets/logo.png
```

Note: VS Code has **no plugin-marketplace manifest** (unlike Claude
`.claude-plugin/`, Cursor `.cursor-plugin/`, Codex `.agents/plugins/`). There is
also no equivalent of the minimal Antigravity `plugin.json`. Distribution is the
copy-into-workspace template above, so this host is intentionally exempt from the
marketplace-boundary checks (§5).

### 2.3 `.agent.md` frontmatter

```yaml
---
name: <recipe-id>                 # e.g. dependency-reviewer
description: |
  <recipe.description, 2-space indented>
tools:                            # scoped by safety posture — see §2.6
  - <tool>
model: <name-or-priority-array>   # see §2.7
user-invocable: true
disable-model-invocation: false   # true only where a workflow must not be auto-picked
target: vscode
---
```

Immediately after frontmatter, every agent body emits the managed markers, the
generated notice, and the host contract, in this order (mirrors
`render_gemini_agent`):

```
<!-- Generated by Endor Labs Agent Kit. Do not hand-edit installed extension cache copies. -->
<!-- endor_agent_kit_managed=true agent_id=<recipe-id> host=vscode -->

# <Recipe Name>

Generated from Endor Agent Kit recipe `<recipe-id>` v<version> for Endor Labs Agent Kit VS Code plugin subagent.
Treat this as a source-first generated artifact; update the recipe and
republish instead of hand-editing installed copies.

## VS Code Host Contract
<... posture-driven contract, see §2.6 ...>

<recipe body — instructions_for_edition(...) verbatim, then action contracts>
```

### 2.4 `SKILL.md` frontmatter

```yaml
---
name: <recipe-id>                 # MUST equal the containing directory name
description: |
  <recipe.description>            # includes "when to use"; ≤1024 chars
---
```

`name` is lowercase/hyphen, ≤64 chars, **no namespace prefix**. The rest of the
file is the notice + VS Code Host Contract + recipe body + action contracts,
exactly as the Gemini `_render_skill` produces (skills omit the `tools`/`model`
frontmatter that agents carry).

### 2.5 `.vscode/mcp.json`

Invariant server id `endor-cli-tools`, CLI-first, no credentials in config. The
only structural difference from every other host is the **top-level `servers`
key** (source root `.mcp.json` and the Cursor package use `mcpServers`):

```json
{
  "servers": {
    "endor-cli-tools": {
      "type": "stdio",
      "command": "npx",
      "args": ["-y", "endorctl", "ai-tools", "mcp-server"]
    }
  }
}
```

The generator must write this from the same source-approved server definition
that produces the root `.mcp.json`, re-keyed to `servers`. Do not embed
credentials, tokens, namespaces, or file paths. MCP stays opt-in: the setup skill
and copilot-instructions must say "do not assume Endor MCP is configured."

### 2.6 Read-only vs mutating tool scoping

VS Code has no `readonly`/`disallowedTools` frontmatter key. Encode the recipe's
safety posture (`source_recipe_safety_posture(recipe)`) by scoping the `tools`
array, and by selecting host-contract prose — the same two levers the Gemini
compiler uses (`_gemini_tools` + `_gemini_host_contract`).

The two mutating agents are `ai-sast-remediation` and `sca-remediation`; all
other 9 workflow agents are read-only. As implemented, `_vscode_tools` mirrors
`_gemini_tools` exactly — including giving read-only agents a shell tool
(`runCommands`), because every read-only workflow runs documented read-only
`endorctl agent api` lookups. The discriminator between read-only and mutating
is therefore `editFiles`/`changes`, not the presence of a shell tool.

| Posture | VS Code `tools` array | Host-contract prose |
| --- | --- | --- |
| Read-only | `codebase`, `search`, `runCommands` | "Keep the workflow read-only … Shell commands, when used, must stay read-only … record missing signals in `data_gaps`." |
| Mutating (approval-gated) | `codebase`, `search`, `runCommands`, **`editFiles`, `changes`** | "Confirm target repo, base branch, diff, validation plan, PR/MR body before editing/pushing/opening. Treat file edits, branch pushes, PR/MR creation, comments, and Endor policy writes as separate approval gates." |

Notes:
- Tool identifiers above are VS Code agent tool-set names. The Endor MCP read
  tools (`check_dependency_for_risks`, `check_dependency_for_vulnerabilities`,
  `get_endor_vulnerability`, `scan`) are **not** enumerated in the `tools` array;
  VS Code exposes the configured `.vscode/mcp.json` server's tools to agents at
  runtime, and the CLI-first path uses `runCommands` for `endorctl agent api`.
  The mapping lives in one place in `compilers/vscode.py::_vscode_tools`,
  analogous to `_gemini_tools`.
- For the two mutating agents, the recipe's approval-gate prose and the
  `actions.yaml` `confirmation_required` semantics (rendered via
  `render_action_contracts`) MUST remain in the body. Tool scoping is a second
  layer of defence, not a replacement for the approval gates.
- Reuse the Cursor/Gemini "Host Contract" pattern, renamed **"VS Code Host
  Contract."** The read-only contract must include "Do not create branches,
  commits, pushes, PRs, or MRs" and "Do not write source files"; the MCP line
  ("Do not assume Endor MCP is configured") appears when the recipe posture uses
  MCP.

### 2.7 Model frontmatter

As implemented, the `.agent.md` frontmatter **omits `model`** entirely; VS Code
uses the model selected in its agent-mode picker. This keeps the generated
artifact honest (model names are not portable across VS Code installs) and avoids
expanding `ALLOWED_SELECTION_MODES`. The `vscode` entry in
`publication/model_recommendations.py` uses `selection_mode: "runtime_selected"`
(already allowed) with `generated_artifact_behavior` = "agent frontmatter omits
model; VS Code uses the agent-mode model picker". The two tiers still apply for
documentation: `complex_remediation` (`ai-sast-remediation`, `sca-remediation`)
and `standard` (the other 9).

Use VS Code file and shell tools only within the recipe safety contract.

## 6b. Shipped artifact: Agent Plugins 1.0 bundle (not a `.vsix` extension)

> **Supersedes §2's overlay/extension format.** The VS Code slice now ships as a
> cross-Copilot **Agent Plugin** (Agent Plugins 1.0), not a `.github/` copy-into-
> workspace overlay and not a `.vsix` extension. Where §2 above describes
> `.github/skills`, `.github/agents`, `.github/copilot-instructions.md`, or a
> `.vscode/mcp.json` with the `servers` key, read the layout below instead.

The publisher emits, at `plugins/vscode/endor-labs-agent-kit/`:

- **`plugin.json`** (`_vscode_plugin_manifest`) — root `$schema`
  `https://agent-plugins.org/schemas/1.0.0/plugin.schema.json`, `name`
